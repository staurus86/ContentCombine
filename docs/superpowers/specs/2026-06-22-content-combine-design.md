## 1. Тезис

Движок автоматизирует рутину редактора: сам собирает материалы из источников, оценивает
их по виральности и качеству, склеивает дубли, переписывает под тон ниши — человек только
подтверждает финальный список. Чтобы запустить **любую** нишу, заполняется ровно **три блока**;
весь остальной конвейер универсален.

Это и есть хук статьи: «комбайн, где редактор делает минимум, а на выходе максимум».

## 2. Граница «движок ↔ ниша»

Нишевый пакет (меняется от ниши к нише) — ровно три вещи:

1. **Источники** — откуда берём материалы (конкуренты): RSS / HTML / Telegram / VK / Bluesky.
2. **Виральные ключи** — словарь ключей и сущностей с весами под тему. Результат отдельной
   keyword-работы. Заменяет зашитый `nlp/game_entities.py`.
3. **Промпты рерайта** — переписывание материала под тон и нишу (+ промпты анализа/склейки).

Движок (универсален, переносится из IgroNews): парсеры, планировщик, circuit breaker /
watchdog / health, скоринг-фреймворк (формула весов, viral, headline), LLM-клиент,
storage, редакторский workflow (статус-машина), веб-админка, пороги.

## 3. Структура каталогов

```
ContentCombine/
├── engine/
│   ├── parsers/      rss, html, telegram, vk, bluesky, proxy
│   ├── scoring/      формула весов, viral_score, headline_score (без игровых слов)
│   ├── llm/          клиент OpenAI/OpenRouter + загрузчик промптов ниши
│   ├── checks/       dedup, freshness, momentum, quality, relevance, sentiment, tags
│   ├── storage/      database (SQLite/PG), sheets, workflow-машина статусов
│   ├── infra/        scheduler, circuit_breaker, watchdog, source_health, observability
│   └── web/          админка, dashboard, queue, settings
├── niches/
│   ├── games/        референс-ниша (текущий IgroNews 1:1) — донор, для проверки отсутствия регрессии
│   │   ├── niche.yaml
│   │   ├── keywords.yaml
│   │   └── prompts/   rewrite.md, analyze.md, merge.md
│   └── seo/          целевая рабочая ниша
│       ├── niche.yaml
│       ├── keywords.yaml
│       └── prompts/
├── main.py           читает ACTIVE_NICHE, грузит пакет ниши, стартует движок
└── docs/
```

### niche.yaml — состав

- `meta`: имя, язык, регион(ы) Google Trends, регион Keys.so
- `sources`: список источников `{name, type, url|channel|handle|group_id, interval, ...}`
- `output`: Google Sheets (id, вкладки), Telegram-канал/бот, пороги уведомлений
- `scoring`: веса формулы (`internal/viral/keyso/trends/headline`) и пороги — переопределяют
  дефолты движка; если не заданы — берутся дефолты

### keywords.yaml — состав

- словарь `term -> weight` (бренды, продукты, сущности, триггеры виральности темы)
- группы синонимов / алиасы для NER-сопоставления
- стоп-слова темы

### prompts/ — состав

- `rewrite.md` — переписывание под нишу (плейсхолдеры: `{title}`, `{text}`, `{tone}`)
- `analyze.md` — прогноз тренда / оценка значимости
- `merge.md` — склейка дублей в один материал

## 4. Главная инженерная работа (расцепление)

| Зашито под игры (IgroNews) | Куда выносим |
|---|---|
| `nlp/game_entities.py` (18 КБ студий/франшиз/платформ) | загрузчик словаря из `keywords.yaml` — **ядро виральности, самая дорогая часть** |
| `SOURCES`, `RU_SOURCES`, `REGIONS` в `config.py` | `niche.yaml` |
| Промпты в `apis/llm.py` (формулировки про игры) | `prompts/*.md` с плейсхолдерами |
| `KEYSO_REGION`, маппинг регион-по-источнику | `niche.yaml` |
| Веса/пороги скоринга | дефолты в движке + переопределение в `niche.yaml` |

`viral_score.py` и формула весов по сути остаются — меняется только источник словаря ключей
(из niche-пакета, а не из захардкоженного модуля).

## 5. Фазы (объём контролирует пользователь)

- **Ф0 — Каркас движка.** Новая папка, переносим движок из IgroNews, выносим игровую специфику
  в `niches/games/`. Критерий успеха: games-ниша поднимается и проходит smoke-конвейер без
  падений; формула скоринга даёт те же числа, что IgroNews, на одном и том же входе.
- **Ф1 — SEO-ниша.** `niches/seo/`: реальные SEO/маркетинг-источники, виральные ключи под тему,
  промпты рерайта под SEO-тон. Критерий: движок поднимается на SEO без правок `engine/`,
  конвейер выдаёт оценённый и переписанный список материалов на ручное подтверждение.
- **Ф2 — Статья.** Повествование + листинги `niche.yaml`/`keywords.yaml`, before/after
  расцепления, скрины «редактор жмёт ОК».

## 6. Входные данные, нужные от пользователя для SEO-ниши (Ф1)

- список SEO/маркетинг-источников (RSS/TG/VK/каналы конкурентов);
- виральные ключи темы с весами (keyword-работа) — можно стартовать с разумного дефолта
  и уточнить;
- желаемый тон рерайта (для `prompts/rewrite.md`);
- куда выводить (Google Sheets id / Telegram-канал) или работать на демо-выводе.

## 7. Что НЕ делаем (YAGNI, пока не запрошено)

- GUI-редактор ниш;
- плагины-парсеры на каждую нишу (парсеры остаются универсальными по типам);
- расширение NLP сверх имеющегося (TF-IDF + словарный NER);
- любые изменения в рабочем IgroNews.

## 8. Открытые вопросы

- Точный список SEO-источников и стартовый словарь ключей — собираем в начале Ф1.
- Вывод SEO-ниши: реальный Google Sheets/Telegram или локальное демо — решаем в Ф1.
