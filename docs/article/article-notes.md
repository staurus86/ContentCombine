# Хабр-статья: инженерный дневник Content Combine

> Живой файл. Сюда складываю всё интересное по механике, решения и «грабли» — материал для статьи. Пополняется по ходу проекта. Не для публикации как есть — это сырьё.

## Хук / тезис
Автоматизировал рутину редактора: машина сама собирает из сотен источников, оценивает виральность, склеивает дубли, переписывает под нишу — **человек только жмёт «одобрить»**. Минимум человека → максимум выхода. И тот же движок работает на **любой** нише — нишу задают ровно 3 блока данных.

## Главная архитектурная идея: «меняем данные, а не код»
- **Движок** (универсальный): парсеры, планировщик, скоринг-фреймворк, LLM-клиент, storage, редакторский workflow, веб-админка, отказоустойчивость.
- **Нишевый пакет** = 3 блока: **источники**, **виральные ключи**, **промпты рерайта**. Всё остальное универсально.
- Доказательство «на живом»: чтобы превратить игровой агрегатор в SEO-комбайн, мы НЕ трогали логику — заменили список `SOURCES` (232 SEO-источника) и словари ключей, и передеплоили. Тот же бинарь, другой конфиг.

## Неочевидная находка №1: виральность держится на ДВУХ словарях
Казалось, «вынести нишу» = поправить один файл сущностей. На деле скоринг опирается на два независимых слоя:
1. `nlp/game_entities.py` — именованные сущности с тирами `S/A/B/C` → дают boost и флаг «крупный тайтл». Чисто data-driven, заменяется один-в-один.
2. `VIRAL_TRIGGERS` — **зашит прямо в `checks/viral_score.py`** (~70 категорий событий с весами). Это главный драйвер очков, и он не выносится через словарь сущностей — правится в коде (или через БД-таблицу `viral_triggers_config`).
> Мораль для статьи: «граница движок/ниша» почти никогда не проходит там, где кажется на первый взгляд. Реальную границу видно только когда лезешь в скоринг.

## Неочевидная находка №2: мультиязычность — это не перевод, а перечисление форм
Матчинг ключей в движке:
- всё приводится к нижнему регистру; **словарь обязан быть в нижнем регистре**;
- совпадение — **по подстроке** (`kw in text`), без стемминга/лемматизации;
- для коротких ключей (≤3 символов) — по границе слова (`\bkw\b`), чтобы `geo`/`aeo`/`икс` не ловили мусор.
Следствия:
- русскую морфологию и языки просто **перечисляем как отдельные строки** (или ловим по стему-подстроке: `фильтр` поймает `фильтра/фильтром`).
- короткие триггеры (<4 симв.) опасны ложными срабатываниями подстроки → выносим их только в сущности (там есть граница слова) либо отбрасываем.
- многие сигналы **языко-независимы** (ChatGPT, Perplexity, Gemini, Core Web Vitals, llms.txt, GPTBot, antitrust) — один токен работает на всех языках.

## Формула скоринга виральности (как считается «важность»)
1. Сумма весов сработавших триггеров `VIRAL_TRIGGERS` (подстрочный матч).
2. **Дедуп по категории**: из триггеров с одинаковым префиксом id (`penalty_*`, `algoupd_*`…) остаётся только самый весомый — чтобы одна тема не накручивала очки 10 раз.
3. + entity boost = вес лучшего тира найденной сущности (`S=30/A=15/B=8/C=3`).
4. + **комбо**: «утечка + крупный тайтл» (+45), «иск + крупная компания» (+20), «скандал + крупный тайтл» (+25), «закрытие + крупный тайтл» (+30). Любопытно: игровые комбо (leak/lawsuit/scandal/shutdown) **без изменений подошли SEO** — Google API leak, антитраст-иски, закрытие сервисов это те же универсальные усилители новости.
5. + календарный boost (окна крупных событий).
6. `score = min(100, score)`, затем уровни high/medium/low по порогам из конфига.
7. **Time-decay**: свежесть умножает очки (<3ч ×1.0, <12ч ×0.9, <24ч ×0.75, <48ч ×0.5, дальше ×0.3) — старое не всплывает.

## Метод: исследование через рой агентов (само по себе материал для статьи)
- **Источники:** 10 параллельных агентов по категориям → 240 сырых → дедуп до **232** уникальных (136 RSS / 34 homepage / 31 Telegram / 29 Bluesky / 2 sitemap), 12 языков, 55% фидов проверены живым запросом.
- **Ключи:** 1 агент картировал код скоринга + 3 агента собрали лексику (EN 168 / RU 168 / intl 158 ≈ 494 термина) с тирами важности.
- Приём: каждому агенту даём **точный формат выходных данных** (готовые dict движка) → результат кладётся в продукт без ручной переразметки.

## Бесплатный режим (важно для «повторяемости» в статье)
Движок поднимается только с `DATABASE_URL`. Бесплатно работают: RSS, HTML-парсинг, Telegram **web-preview** (без API), Bluesky (открытый API), Google Trends. Платное (LLM-рерайт, Keys.so-частотность, VK) — выключено и изолировано: падает по одному источнику, **circuit breaker** глушит после 5 фейлов, watchdog перезапускает. Никакой «всё рухнуло из-за одного фида».
- Честная деталь: 45% фидов взяты как `homepage`/best-guess; движок сам отвалидирует и отключит мёртвые. Не выдаём непроверенное за проверенное.

## Что особенно «по-русски» в виральности SEO
Яндекс-специфика, которой нет у Google: именованные фильтры **Минусинск, Баден-Баден, АГС**, свежие **Тайфун** (фильтр AI-текстов, апр.2025), **Оригами** (экспертность автора), **Вега**; накрутка ПФ; ИКС; нейроответы / Поиск с Алисой / YandexGPT; Share of Voice в Вебмастере (новая метрика AI-видимости). Рунет-сообщество реагирует на это сильнее, чем на любой Google-апдейт.
